# Фронтенд для Общего Дела

Next.js 16 (App Router) поверх WordPress REST API. Документация по проекту — в [`docs/`](./docs/README.md): состояние работ, дизайн-система, бэкенд, миграция на прод.

## Переменные окружения

Обязательные:

| Поле        | Описание                                                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WP_USER     | username из админки wordpress                                                                                                                                                |
| WP_PASSWORD | Сгенерированный application password                                                                                                                                         |
| WP_BASE     | origin сервера WordPress, без `/wp-json` и без слэша на конце. Пример: `https://od-dev.tmweb.ru`. К значению в коде добавляется `/wp-json`, поэтому путь указывать не нужно. |

Необязательные:

| Поле              | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WP_MEDIA_CDN      | origin бакета с медиа. Значение по умолчанию задано в коде (`src/shared/api/mediaCdn.ts`), поэтому переменную можно не задавать. `WP_MEDIA_CDN=""` полностью отключает подмену URL картинок.                                                                                                                                                                                                                                                                                                                                                                    |
| KINESCOPE_TOKEN   | API-токен Kinescope. Нужен **только** скрипту `film:kinescope`, в рантайме не используется.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| WP_LEGACY_BASE    | origin старого сайта, откуда фолбэк (A6) забирает ещё не переверстанные страницы: `app/legacy/[...slug]/route.ts` проксирует их, а catch-all показывает в iframe. Сейчас это живой прод `https://obshee-delo.ru`; когда появится «замороженная» копия, переключение — смена одного этого значения, без правок кода. Из значения берётся только origin (схема + хост + порт), путь и query отбрасываются. Если переменная не задана, фолбэк выключен: `/legacy/*` отвечает 404, а старые страницы отдают 404 ровно как сегодня — сборка и CI при этом не падают. |
| REVALIDATE_SECRET | Общий секрет для `POST /api/revalidate/` — точечного сброса кеша, когда контент правят в WordPress (B4). Пока переменная не задана, эндпоинт отвечает 503 и ничего не сбрасывает. У каждого стенда должен быть **свой** секрет: секрет прода на стейдже — это доступ к кешу прода. В отличие от остальных, читается на каждый запрос, так что перезапуск после правки не нужен. Как это подключается со стороны WordPress — [`docs/wp-backend.md` §6.5](./docs/wp-backend.md).                                                                                  |

Значения читаются один раз при старте процесса, поэтому после правки `.env` дев-сервер нужно перезапустить. `WP_BASE` и `WP_MEDIA_CDN` вдобавок влияют на список разрешённых хостов картинок (`images.remotePatterns` в `next.config.ts`), который вычисляется **на этапе сборки** — в докере их надо передавать как build-args, иначе `next/image` будет отвечать 400.

## Локальная разработка

Приложение в дев режиме можно запустить внутри докер контейнера или локально.

### Общие шаги

1. Создать пароль по [инструкции](https://make.wordpress.org/core/2020/11/05/application-passwords-integration-guide/) в админке wordpress.
2. Создать файл `.env`
3. Добавить `.env` переменные `WP_USER`, `WP_PASSWORD` и `WP_BASE`

### На локальной машине

1. Установить `nvm`
2. Запустить `nvm use`
3. Активировать `pnpm` через corepack (поставляется вместе с Node.js) - `corepack enable && corepack prepare pnpm@11.3.0 --activate`
4. Установить зависимости - `pnpm i --frozen-lockfile`
5. Запустить проект в дев режиме - `pnpm dev`

### Внутри Docker container

Для запуска nextjs приложения внутри контейнера для локальной разработки:
`docker-compose up --build frontend-local`

## Команды

| Команда                     | Что делает                                                                                                                                         |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`                  | дев-сервер (Turbopack). `pnpm dev:debug` — то же с `--inspect`                                                                                     |
| `pnpm build` / `pnpm start` | сборка для прода / запуск собранного приложения                                                                                                    |
| `pnpm lint`                 | ESLint по всему дереву, `--max-warnings 0`                                                                                                         |
| `pnpm lint:styles`          | Stylelint по всем `*.css` с автофиксом                                                                                                             |
| `pnpm type-check`           | `tsc --noEmit` (типы ESLint не проверяет)                                                                                                          |
| `pnpm format`               | Prettier                                                                                                                                           |
| `pnpm test`                 | Vitest. `test:watch` — вотчер, `test:coverage` — покрытие                                                                                          |
| `pnpm test:e2e`             | Playwright. `test:e2e:ui` — в UI-режиме. Нужен запущенный дев-сервер                                                                               |
| `pnpm generate:types`       | перегенерировать типы WP API из OpenAPI-схемы                                                                                                      |
| `pnpm url:check`            | проверить, что реальные адреса старого сайта не отдают 404 (по выгрузке «Страницы входа» из Яндекс.Метрики). `-- --base https://…` — против деплоя |
| `pnpm pages:inventory`      | сколько страниц WP заредизайнено, сколько отдаётся как есть, сколько осталось на A6-iframe — плюс доля трафика каждой группы. `-- --list passthrough` — полный список |

Перед пушем прогоняются те же проверки, что и в CI: `pnpm lint && pnpm type-check && pnpm test && pnpm build`. На закоммиченных файлах husky + lint-staged дополнительно гоняют `eslint --fix` и `prettier`.

## Заполнение данных по фильмам (ACF `group_film_meta`)

Все 18 полей фильма (`kinescope_id`, `watch_url`, `trailer_url`, ссылки на соцсети,
плакат, до 5 слотов «скачать») заполняются через CSV-таблицу — редактор правит её
в Excel или Google Sheets, скрипт записывает изменения обратно в WordPress.

Базовый цикл:

```bash
pnpm film:export                 # выгрузить .scratch/film-worksheet.csv (99 фильмов каталога)
# … заполнить пустые ячейки в таблице …
pnpm film:import                 # показать, что изменится (ничего не пишет)
pnpm film:import -- --apply      # записать в WordPress
```

Все скрипты (`scripts/`, без зависимостей, читают `.env` через `node --env-file`):

| Скрипт                | Что делает                                                                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm film:export`    | выгружает таблицу, все колонки уже заполнены текущими значениями из WP                                                                         |
| `pnpm film:import`    | пишет заполненную таблицу обратно. **По умолчанию dry-run**, пишет только с `--apply`                                                          |
| `pnpm film:kinescope` | подставляет `kinescope_id`, сопоставляя фильмы с библиотекой Kinescope. Нужен `KINESCOPE_TOKEN`. Правит таблицу на месте — потом `film:import` |
| `pnpm film:covers`    | загружает обложки из экспорта телеграм-канала и ставит их featured-картинкой. Трогает только фильмы **без** обложки                            |
| `pnpm film:posters`   | заполняет `poster_image_url` лучшим из того, что уже есть на сайте: (1) плакат с Яндекс.Диска — либо файл по ссылке «Скачать плакат», либо named-файл внутри общей папки из таблицы `FOLDER_POSTERS` в самом скрипте (папка держит один плакат в шести вариантах, выбор файла — ручной); качает и кладёт в медиатеку, (2) картинка с «плакат/постер» в имени из тела поста, (3) featured-обложка фильма (горизонтальная, пишется вариантом `large` — сайт читает `-WxH` как пропорции карточки). Плакат никогда не перезатирается, обложка из п. 3 пересчитывается каждый запуск |
| `pnpm film:remap`     | переносит заполненную таблицу между окружениями: сопоставляет по названию и переписывает id постов (id у od-dev и прода разные)                |

Правила:

- Пустая ячейка **ничего не стирает** — записываются только заполненные и изменённые
  значения, поэтому таблицу можно заполнять по частям. Чтобы очистить поле, поставьте `-`.
- Колонки `hint_*` — подсказки, найденные в старом теле поста (ссылки на YouTube и
  Яндекс.Диск). Скрипт их **не** записывает: перенесите нужное в обычную колонку вручную.
- `--delimiter ';'` — для Excel с русской локалью, `--all` — все 203 поста `format=video`,
  `--only 70570,71933` — только указанные фильмы, `--in` / `--out` — путь к таблице.
- Все скрипты идемпотентны: повторный прогон на неизменённой таблице даёт пустой diff.

Порядок при переносе на другое окружение — `export` → `remap` → правки руками →
`kinescope` → `import --apply` → `covers --apply`. Подробности и подводные камни:
[`docs/prod-migration-runbook.md` §3](./docs/prod-migration-runbook.md). Что именно
осталось заполнить и кто это делает — B-VIDEO2 в
[`docs/implementation-plan.md`](./docs/implementation-plan.md).
